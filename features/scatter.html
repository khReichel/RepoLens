What it shows

  • Four quadrantsHotspot (high complexity, high churn — act now), Non-critical (low complexity, high churn), Legacy risk (high complexity, low churn — dormant danger), Healthy (low on both). Bubble size = code age.
  • Code MapTreemap view: area = Lines of Code, colour = risk score. A dominant red block is impossible to ignore in a board presentation.
  • Trend AnalysisComplexity, LOC, Silo Ratio and Commits over time per module — so you can see whether things are improving or deteriorating.
  • Module Change FrequencyTotal commits per module with main contributor — reveals "god modules" absorbing disproportionate maintenance effort.

When to use it

Quarterly planning

Walk into an architecture review with a scatter plot instead of gut feelings. Every module's position is a data point, not an opinion.

Refactoring prioritisation

Move from "this code feels messy" to "this module is in the top-right quadrant with a rising trend — it has priority."

CTO / board reporting

A Code Map with a dominant red block communicates codebase health more clearly than any written report.
